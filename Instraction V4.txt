# 6. PROPERTY REQUEST PROBLEM

Sometimes the customer asks for a specific property, project, location, unit type, reference number, budget, or other real-estate requirement, but the AI:

- sends the wrong property;
- fails to send a property;
- performs an overly broad search;
- misunderstands the requested property;
- returns unrelated inventory;
- invents property information;
- fails to preserve previously supplied requirements;
- sends text instead of the correct property information/media;
- loses context between consecutive messages.

Investigate this deeply.

The upgraded architecture must prioritize deterministic property retrieval.

For example:

```text
Customer asks for exact property reference
        ↓
Exact reference lookup FIRST
        ↓
Verified org-scoped property record
        ↓
Availability validation
        ↓
Send exact verified data/media
```

Only if an exact match does not exist should broader property matching be considered.

The system should progressively understand:

- reference number
- project
- building
- community
- area
- sale/rent
- property type
- bedroom count
- budget
- minimum price
- maximum price
- size
- ready/off-plan
- developer
- amenities
- investment objective
- ROI requirements
- distress-deal intent
- previous property already shown
- rejected properties
- customer preferences stored in conversation memory

The LLM must never invent a property.
